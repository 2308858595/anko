# 安科 · あんこスレ

一个纯前端的**安科**游戏。模型担任「导游」，现场写剧情、抛出 10 个走向；
路上凡是拿不准的事，全都当场掷骰——判定、极性、D10表、好感、暗骰，一个不少。

> 安科起源于日本 AA 漫画。作者写一段剧情后自设约 10 个候选走向（第 10 项通常是「？？？？」），
> 用骰子决定走哪一条——剧情因此既连贯又完全不可预测。

## 跑起来

只有一个文件，双击 `index.html` 就能玩。想用本地服务器（推荐，存档更稳）：

```bash
python3 -m http.server 8777 --directory /Users/kevin/Claude/anko
```

## 开局骰

安科开场的传统：在写第一个字之前，先把世界和主角**全部交给骰子**。

**属性名由模型按题材自拟**，不套固定模板——没有魔法的故事就不该有「魔力」这一项。实测：

| 剧本 | 摇出来的属性 |
|---|---|
| 昭和侦探 | 洞察眼力47・警方门路73・怪异知识47・烟酒耐受20・钱包厚度18・异性缘分21 |
| 三国外卖 | 电量极限控制术87・话术与甩锅甩包袱77・载具骑行74・冷兵器徒手搏击27・遇险心理承受力13 |
| 幻想乡挑战者 | 力量81・敏捷65・耐力37・魔力1・意志21 |

提示词要求至少留 1～2 项明显更低的骰式——**短板比长处有趣得多**，一个低到离谱的数值能撑起整篇的笑点。
属性会挂进后续的 `[检定]`，所以短板是真的会翻车的。

## 一个回合是怎么走的

```
上一回的 1D10 结果
      ↓
【判定阶段】导游声明这一回要交给骰子的事（3～5 项）
      ↓
   app 用 crypto 逐条摇骰，动画逐条揭示
   （D10表骰出 10 → 回头要一批更离谱的选项重摇，最多三层）
      ↓
【书写阶段】导游拿着已定的点数写正文，把结果演出来
      ↓
【走向阶段】另开一次调用，专门生成 10 个走向并避开已用过的
      ↓
玩家掷 1D10 决定下一步走向（或安价手选）
```

一回合基础 2 次调用；开了「走向单独生成」是 3 次；骰出 `？？？？` 时每升一级再加 1 次。

**关键在于顺序**：导游必须在看到点数**之前**就承诺判定内容，所以它没法为了顺手而挑数字。
这也是设置里「判定阶段」开关的含义——关掉会退回单次调用，省一半钱，但判定的诚实性会打折。

## 判定系统

| 类型 | 用途 | 结算 |
|---|---|---|
| `[D100]` | 能否做到 | 总值 ≥50 成功。带具名加值，如 `(+40 愤恨, -20 临危不乱)` |
| `[检定]` | 用人物卡属性判定 | `1D100 + 该属性 + 加值` 对比难度 |
| `[极性]` | 二选一 | 低骰取 A，高骰取 B |
| `[光谱]` | 落在连续谱上 | `《完好——断裂》`，给 0～100 的位置 + 位置条 |
| `[D10表]` | 多选一 | 按区间取项；**骰出最大面**则导游自由发挥一个更离奇的结果 |
| `[分档]` | 一骰多档 | `《>30 罚款｜>50 拘留｜>70 判刑》`，取达到的最高档 |
| `[骰 1D30+150]` | 任意骰式定数值 | 身高、天数、人数、金额 |
| `[好感]` | 关系结算 | d100 → -3～+3 |
| `[暗骰]` | 隐藏心思 | 摇了但不公开，只让它影响角色言行 |

**大成功 / 大失败**只对「成不成功」有意义的判定生效（`[D100]` `[检定]` `[好感]` `[暗骰]`）：
96-100 大成功，1-5 大失败。身高、人数、光谱位置这类骰出极值只是极值，不会被判成「大成功」。

**光谱的中间值就是中间值**。端点一律用「」引起来当标签，并附上百分位和一条位置条，
所以 45 会读成「正卡在两者中间（45/100）」而不是「略偏完好」——避免中间值被写成一边倒。
提示词也要求端点写成短的可分级词（`完好——断裂`），不要写「微毫无损」这类已经说死的绝对句。

**好感度换算表**（与原帖一致）：

```
1~15 → -3    16~30 → -2    31~45 → -1    46~55 → 0
56~70 → +1   71~85 → +2    86~100 → +3
```

初次见面时，非大成功/大失败的结果会被钳制在 16~85 之间——所以初见不会一上来就 ±3。

骰点行按骰娘格式渲染，穿插在正文中间：

```
判定  主角面对异象的镇定程度（+20 摸鱼三年的厚脸皮）
【ROLL：1D100+20 = 70+20 = 90】 成功
```

## 大判定：会弹掷骰页面的那种

会让剧情真正分叉的判定——「萌百娘的同桌是怎样的人」「推门进来的是谁」——值得让读者看着骰子落下。
导游在类型后加 `!` 来标记，例如 `[D10表!]` `[极性!]`，**每回合最多标一项**。
被标记的判定会弹出和主骰一样的掷骰页面：选项列表在下方，骰子转停后高亮选中的那条。

**`[D10表!]` 必须给满 9 个各不相同的选项，一个骰面一个**——和主选项同等规格，
不是三四项去分区间。第 10 面固定是 `？？？？`，系统自动补。这正是萌娘百科词条里那个招牌形态：

```
1D10 = 3   萌百娘的同桌是怎样的人
1  总是睡不醒的重度中二病少年
2  看起来非常完美的学霸委员长
3  手上拿着奇奇怪怪道具的科技宅   ← 选中
…
9  极其普通但吐槽极其精准的归宅部
10 ？？？？
```

本来就只有两种可能的（是/否、他/她）用 `[极性!]`，不必硬凑九项。

没标记的普通 `[D10表]` 给 3～4 项按区间分就行，只是正文里的一行骰点，不打断阅读。
给几项就把 1～9 均分成几段（3 项 → 1-3/4-6/7-9，5 项 → 1-2/3-4/5-6/7-8/9）。
想让所有分叉表都弹页面，可以在设置里打开「所有 D10表 / 极性 都算大判定」。

### 骰出 10 → 换一批更离谱的重摇

`？？？？` 不是「导游随便写」。骰到 10 时系统会**回头找导游要 9 个明显更离谱的新选项**，
再摇一次；新表的 10 还能继续升级，最多三层。实测：

```
同桌是怎样的人  《平凡靠谱的普通学生｜高冷学霸｜看着像不良其实很老实》
【ROLL：1D10 = 10】  ？？？？ → 换一批重摇
  升级1  《未来来的监视者｜穿校服的野生大猩猩｜服务器过热幻化的幽灵｜
          课桌下用高压锅炼丹的修仙大能｜装十三岁的卧底刑警｜带八个保镖的石油王室继承人｜
          立牌+蓝牙音响装成的虚拟主播｜凑不齐饭钱的落魄魔王｜连营养舱一起抬进教室的昏迷奇人》
  【ROLL：1D10 = 6】  带了八个黑衣保镖把教室围得水泄不通的沙特石油王室继承人
```

## 走向单独生成（默认开）

10 个走向另开一次调用，不跟正文挤在一起——写在几百字散文末尾的选项容易和往回合雷同。
单独生成时会把**本篇已经出现过的走向全部列出来**要求避重，并强制覆盖六个方向
（稳妥／冒险／交涉／动手／离奇／跑题）。

实测连续 3 回共 27 个走向，跨回合字符 bigram 平均相似度 **0.024**，近重复项 **0** 个。
想省钱可以在设置里关掉，退回「正文和选项一次生成」。

## 作弊模式（默认关）

默认一切听骰子的，**不打断正常流程**。开了之后，每一项判定旁边多出三个小控件：

| 控件 | 作用 |
|---|---|
| `★` | 把这一项标记成大判定，重写本回合时会弹掷骰页面 |
| `↻` | 只重掷这一项 |
| 数字框 + `✓` | 直接指定这一项的骰面点数 |

改完想改的，再按 **「⟳ 用这些点数重写本回合」**（判定不变，让导游重写一遍）
或 **「↻ 全部重掷并重写」**。好感度与线索台账会跟着回滚重算，不会留下已撤销回合的账。

## ⚡ 快速模式

顶栏的 ⚡ 一键开关（设置里也有）。跳过掷骰动画直接出结果，一次大判定从 2.5 秒缩到 0.6 秒，
结果仍会停留足够读一眼。判定逐条揭示的间隔也从 320ms 压到 40ms。


## 言论交锋

争论爆发时导游会声明一场交锋，app 按拔河规则模拟：

- 双方各投 N 个 d100 加各自加值，比总和，赢的一方推进「优势」一格
- 优势推到 ±3 分出胜负；**第 4 回合起每三回合推进格数 +1**，防止拉锯太久
- 特性：`奖励骰`（每骰投两次取高）、`领先加骰`（优势为正时多一骰）、`免疫骰`（多一颗不受干扰的骰）

全程真随机。战况表**逐回合当场揭示**——每一回合双方的每一颗 d100 都摊开给你看，
优势条随之推进，最后才出胜负，然后才交给导游写台词与 `[证物]`：

```
言论交锋  魔理沙用弹幕决斗申请行政复议
魔理沙 ▓▓▓░░░ 亚瑟（IRS）
第1回  魔理沙 51+38+26 = 115    亚瑟 35+110+103+79 = 327   优势 -1
第2回  魔理沙 97+102+41 = 240   亚瑟 115+103+71+107 = 396  优势 -2
第3回  魔理沙 54+23+107 = 184   亚瑟 69+44+68+114 = 295    优势 -3
亚瑟（IRS）取得了胜利
```

（亚瑟 4 颗骰是「免疫骰」多给的那一颗，加值 +20；魔理沙 3 颗 +10。）

## 其它

- **导游吐槽**：正文里 `//` 开头的行，渲染成紫色旁注。大成功大失败时尤其毒。
- **场景抬头**：每回的时间与地点。
- **线索收集**：`[线索已收集]` 卡片，顶栏 📖 可查全部线索与好感度台账。
- **？？？？**：第 10 项固定是它，骰中会追加 **1D2**（1 = 大成功，2 = 大失败）决定超展开的方向。只能靠骰子交出来，不能安价指定。
- **安价**：可以放弃掷骰直接点选 1–9，或自己写一个走向。想要纯粹安科体验就在设置里关掉。
- **导出**：整局存成 Markdown，含每一次骰点与好感度结算。
- **续档**：自动写入 localStorage。

## 设置

| 项 | 说明 |
|---|---|
| **API Key** | OpenRouter 的 key，存在浏览器 localStorage。 |
| **模型** | 从 OpenRouter 拉取全部可用模型（300+），也可直接输入 ID。默认 `~google/gemini-flash-latest`（`~…-latest` 是滚动指针，永远指向该系列最新版，不用手动跟版本）。 |
| **混沌度 1–5** | 1 = 写实克制，3 = 平衡，5 = 打破第四面墙、乱入、时空错乱。 |
| **开局骰** | 关掉就跳过建卡直接开场，后续也不会有 `[检定]`。 |
| **大判定走掷骰页面** | 默认开。关掉则任何判定都不弹掷骰动画。 |
| **快速模式** | 跳过掷骰动画。顶栏 ⚡ 可一键切换。 |
| **省钱模式** | 关闭模型思考，省约 2/3 花费。见下。 |
| **作弊模式** | 见上。默认关。 |
| **意外事件池** | 一行一条。每回合摇 1D100，≥85 时随机抽一条塞进剧情——对应原帖的「长期安价：今天会发生的意外」。 |
| **判定阶段** | 关掉退回单次调用，省钱但判定诚实性打折。 |
| **完整保留的回合数** | 上下文里保留多少个「带选项」的完整回合；更早的回合只留正文。 |
| **自动压缩前情** | 默认开。更早的回合攒够长度就压成一份「前情提要」，之后不再进 prompt。见下。 |

顶栏实时显示累计花费与 token 数，格式 `$0.0123 / $2.00`。开着判定阶段时每回合约 6～7k token。
**一局最多花 $2，到顶硬停**，见下。

## 实现要点

- **单文件**，无依赖、无构建、无后端。直接 `fetch` OpenRouter（其 API 开了 `Access-Control-Allow-Origin: *`）。
- **骰子真随机**：`crypto.getRandomValues` + 拒绝采样消除取模偏差。主骰的点数在动画开始前就已确定，动画纯粹是表演。
- **判定位置**：导游在正文里写 `【判定N】` 独立行标记骰点发生的位置，app 把渲染好的骰点块插到那里；没被放置的会统一补到段首。
- **上下文压缩**：较早回合只把正文送回模型，丢掉当时的选项列表与判定明细。
  压缩边界**对齐到 4 的倍数**，不是每回合往前挪一格——否则每回合都会有一个回合从
  「完整原文」翻成「压缩正文」，等于改写历史中段，前缀缓存必然失效。
  再往前的回合会被**折成一份前情提要**（下面单开一节）。
  对齐后 11/13 的回合能保持整段前缀稳定（实测），边界每 4 回才动一次。

- **容错**：格式解析容忍全角等号、Markdown 包裹、编号用顿号或全角句点；完全不打标记时退化成「第一条 `1.` 之前都算正文」。localStorage 被禁用时（隐私模式、`data:` URL）自动降级为纯内存运行。
- **掷骰页面按类型分发**。任何一种判定都可能被标记成大判定（`[D100!]` 也是合法的），
  所以 `bigRollView` 必须覆盖全部 kind：polar 列两端、table 列区间、tier 列档位、spectrum 列两极、
  其余（判定/检定/好感/暗骰/骰/属性）没有可列举的选项就只报结果。
  以前除 polar 外一律走 table 分支，一个没有选项的 `[D100!]` 会让 `tableRanges` 拿到空数组直接崩。
- **`【判定N】` 标记**是行内扫描的，不是整行锚定。模型经常把两个写在一行（`【判定4】【判定5】`）
  或夹在句子中间，整行锚定会一个都匹配不上、把标记当正文渲染出去。
- **`[好感]` 只用于「角色甲对角色乙」**，产出 -3～+3 的关系值。模型常拿它去量
  「某人对某事的警惕程度（0为…100为…）」——那是 0-100 的量表，套进 -3～+3 会得出毫无意义的数字，
  还会往好感台账里塞进一本书。现在会就地识别（看有没有「对」、B 侧是不是以「程度／态度／指数」结尾、
  有没有「0为…100为…」的写法）并改判成 `[光谱]`，**连两端都能从括号里救出来**：
  `(0为"好好玩"，100为"立即扔掉")` → 两端「好好玩／立即扔掉」，48 读作「正卡在两者中间（48/100）」。
- **`《》` 只对用选项的类型才是选项**。`[D100] 能否读懂《人间失格》` 这种书名会原样留在标签里，
  不会被当成选项抠走（以前会把标签截成「能否读懂」）。
- **判定行解析**容忍模型的各种行首修饰：`**加粗**`、`- ` `* ` `• ` 项目符号、`> ` 引用号、`1.` `1、` 编号、全角 `【】`。
  这些不是洁癖——对话一长模型就开始加 markdown 装饰，以前一加就整行匹配失败，
  那一回的判定会**静默消失**（正文照写，就是一颗骰子都不摇）。判定申请解析为空时现在会重试一次并提示。
- **选项解析**的几个坑都踩过并修好了：选项内部可以嵌书名号（`能弹奏《欢乐颂》的电子琴`，取最外层的一对）、
  可以整项都是书名号（`《人间失格》｜《海边的卡夫卡》`）、分档选项内部含 `>`、结尾 `》` 被模型截断也能救回。
  真解析不出来时会降级成 D100 **并在 console 打一条 warning**——静默降级曾经把这个 bug 藏了很久。

## 关于 prompt 缓存

OpenRouter 上**必须显式打 `cache_control` 断点**——包括文档里写着「自动缓存」的 DeepSeek，
实测不打断点一样是 `cached_tokens=0`、全价重算。本项目在两处打了断点：
系统提示词末尾，以及压缩历史区的末尾（后者靠上面的 BLOCK 对齐保持稳定）。

同一段 6.4k 前缀重复三次的 A/B（读 API 返回的 usage）：

| 模型 | 无断点 | 有断点 | |
|---|---|---|---|
| `google/gemini-3.6-flash` | cached=0，$0.009714 | cached=6413，**$0.001064** | −89% |
| `deepseek/deepseek-v4-flash` | cached=0，$0.000455 | cached=5120，**$0.000155** | −66% |

真实对局里的命中情况（默认模型，每回合三次调用）：

```
第1回  1609/0     1252/0     1191/0      ← 前缀太短，够不到最小可缓存长度
第2回  2552/1536  2231/768   1924/0
第3回  4292/2304  3899/1792  1980/0
第4回  6006/4096
```

开局几回因为上下文太短吃不到缓存（Gemini 系最小 1024～4096 token），之后随上下文增长命中越来越多。

**已知没吃到的一处**：每回合第三次调用（走向生成）恒为 0——`optsPrompt` 把「已出现过的走向」
列进了 system，每回合变长，前缀天然不稳定。要修得把避重列表挪到消息尾部，目前没做。

> 注：`/api/v1/activity` 需要 management key，普通 key 拿不到（403），所以以上是按调用实测而非查控制台历史。
## 省钱模式（默认开）

Gemini Flash 这类模型会先「思考」一大段再写正文，而**思考 token 要计费、你还看不到**。
实测同一段 300 字正文：

| 设置 | 输出 token | 其中思考 | 成本 | 正文长度 |
|---|---|---|---|---|
| 默认 | 799 | 524（66%） | $0.00602 | 336 字 |
| `effort: minimal` | 257 | **0** | **$0.00196** | 333 字 |

正文长度和质量没差别，钱省了三分之二。所以默认发 `reasoning: {effort:"minimal"}`。
（顺带一提 `reasoning:{enabled:false}` 在这个模型上**不生效**，照样思考——必须用 `effort`。）

实跑一整回合（三次调用）：思考占比从 66% 降到 10%，成本 $0.0332 → **$0.0113**。
想要模型多想想就在设置里关掉。

## 自动压缩前情（autocompaction，默认开）

只有「保留最近 N 回完整原文」这一档是不够的：更早的回合虽然退成了一行正文，
可**正文本身一个字都没少**，上下文照样随回合数线性变长。第 40 回的每一次调用，
都要把前 39 回的正文重付一遍钱。

所以压缩区攒够 **9000 字**（约 10～14 回）就整段交给模型写成一份**前情提要**，
那些回合从此不再进 prompt。提要是**增量**的：下一次压缩把上一份提要连同新折叠的回合
一起交上去重写一份，覆盖范围只增不减，所以 prompt 有上界。

实测（每回合正文约 700 字、完整保留 3 回）：

| | 消息条数 | prompt 字数 |
|---|---|---|
| 第 20 回，关掉压缩 | 42 | 14958 |
| 第 20 回，开着压缩 | 11 | **2119** |
| 第 36 回，开着压缩 | 11 | **2094** |

第 36 回和第 20 回一样大——这就是重点。

几个细节：

- 压缩**只影响发给模型的东西**。页面上的正文、存档、导出，一个字都不动。
- 折叠边界永远踩在 4 的倍数上（和上面的缓存对齐同一套），提要本身单独占一个
  `cache_control` 断点：它十来回才变一次，是很稳的前缀。
- 压缩请求发的是**单条 user 消息、不带 system**，也就不打缓存断点——这段输入折叠完
  就再也不会出现，缓存它是白花钱。
- 提要短于 60 字就判定失败、这次不压（宁可多花一回合的钱，也不能把一句废话
  当成前 20 回的记忆塞进去）。压缩失败不连累当前回合，本回合退回完整历史继续写。
- 台账（📖）里能看到当前提要全文和「原文 11319 字 → 提要 380 字」。
  模型对早期剧情的记忆就只剩那一段，值得偶尔翻一眼。

## 一局最多 $2

`COST_CAP = 2`（`index.html` 顶部）。这一局累计花到 $2 就**一个请求都不再发**——
不是提醒，是硬停。顶栏的花销标签七成变黄、到顶变红，掷骰按钮换成「导出 / 新开一局」。
新开一局重新计数。

闸门开在 `streamChat` 的第一行，所有调用都从那儿过，漏不掉；入口（`nextTurn`、
`dockRoll`、`redoTurn`）另外拦一道，免得点下去才被拒。超出的上限是**一次调用**：
判定阶段花完最后的额度，写正文那一次就会被拦下，实测停在 $2.005。

顺带修了一处会让上限失效的账：

```js
game.cost += (+usage.cost || +cd.upstream_inference_cost || 0);   // 旧
game.cost += (+usage.cost || 0) + (+cd.upstream_inference_cost || 0);   // 新
```

BYOK 的请求 `usage.cost` 是 0（OpenRouter 不收推理费），真正的钱在
`cost_details.upstream_inference_cost` 里（实测 `cost:0` + `upstream:0.0014955`）。
写成 `||` 的话，只要哪天两边都非 0，上游那一大笔就整个漏掉了。

> 这是**页面里**的上限，护的是自己这一局别玩脱。它拦不住绕开页面直接打代理的人——
> 那一层归 Worker 的限流（每 IP 每 60 秒 40 次）和 OpenRouter 后台给 key 设的月度额度管。

## 在 OpenRouter 后台认出是哪篇安科

每次请求都带上这一局的标题，后台一眼能看出这些 token 烧在哪个故事上。

用的**不是** `X-Title`——那是 app 的**显示名**，而 app 的身份由 `HTTP-Referer`
那个 URL 决定（文档原话：*primary identifier for rankings*）。每回合换一次
`X-Title`，只会把 openrouter.ai 上同一个 app 的名字反复改写，什么也分不出来。

按请求落库的是 body 里这两个字段：

| 字段 | 内容 | 在哪看得到 |
|---|---|---|
| `user` | 标题，如 `魏玛共和国的最后一夜` | activity 页面的 **Client User ID** 列 |
| `session_id` | `标题 · 局号`，如 `…最后一夜 · 21cad29d` | `/api/v1/generation` 记录；同一篇开过几局可以分开 |

`X-Title` 保持固定的 `Anko Player`，`HTTP-Referer` 固定 `http://anko.kapp.pp.ua`
（Worker 里是单独的 `APP_URL` 变量——`ALLOW_ORIGIN` 是逗号分隔的列表，整串塞进
`HTTP-Referer` 不是合法 URL）。

几个实测出来的坑：

- **`session_id` 超过 256 字符上游直接 400**。标题是玩家自由输入的，客户端和 Worker
  两边都截；先截标题再拼局号，保证局号不会被切掉。4000 字的标题直连必炸，走代理是 200。
- **`metadata` 收 200 但查不到**。请求带上 `metadata:{...}` 不报错，可同一条
  `/api/v1/generation` 记录里根本没有这个字段，超长值也不校验——写进去等于写进黑洞，所以不发。
- Worker 会剥掉标签里的控制字符再截断。浏览器传什么长度都不能信。

## 发布

内置了一个 OpenRouter key，开箱即用。**但这是静态页面，key 藏不住**——
任何访客打开 DevTools 的 Network 面板，第一个请求的 `Authorization` 头就是明文。
混淆、编码、拆分都没用。

所以这个 key 的安全性完全靠 OpenRouter 那一侧兜底，两道：

1. **模型白名单（guardrail）**：这个 key 只放行 Gemini Flash 一系。
   拿它去调 Claude / GLM 会直接被拒：
   `No endpoints available matching your guardrail restrictions`
2. **消费上限**：在 OpenRouter 控制台给这个 key 设月度上限，泄露了也就损失这么多。

> 注意：创建 key 的 REST API（`POST /api/v1/keys`）**没有**模型白名单字段，
> 只有 `limit` / `expires_at` / `include_byok_in_limit` 那几个。
> 白名单要在控制台的 guardrail 设置里配。

访客想换模型，可以在设置里填**自己的** key —— 直连 OpenRouter、模型随便挑、费用走他们自己的账号，
完全不碰内置额度。

### 托管到 GitHub Pages

只有一个 `index.html`，推上去、在 **Settings → Pages** 里把 Source 设成 `main` / `root` 就行。

```bash
git init && git add index.html README.md
git commit -m "安科"
git branch -M main
git remote add origin git@github.com:<你>/<仓库>.git && git push -u origin main
```

要换掉内置 key，改 `index.html` 顶部的 `DEFAULT_KEY` 即可。
